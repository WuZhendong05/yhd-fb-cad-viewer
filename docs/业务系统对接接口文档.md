# 外部业务系统对接接口文档（CAD 模型上传与查看）

> 版本：v1.0　|　适用服务：`cad-viewer-upload-api`　|　更新：2026-08-21

本文档面向**业务系统的开发人员**，说明如何通过 HTTP 接口提交 STEP 零件（及加工特征 JSON），并获取一个可直接打开查看模型的浏览器 URL。

---

## 1. 概述

业务系统将 **STEP 文件**（`.step` / `.stp`）与**加工特征 JSON 文本**通过本接口上传；服务端将文件落盘，并返回一个 **`viewerUrl`**。最终用户（或业务系统）打开该 URL，即可在浏览器中查看模型（Three.js 渲染），并展示特征识别高亮。

整体数据流：

```
业务系统 ──POST──▶ 上传 API(:8420)  ──返回 jobId──▶ 轮询状态
                                              │
                    拿到 result.viewerUrl（status=landed）
                                              ▼
          最终用户浏览器 ──打开──▶ CAD 查看器(:3245) 渲染模型 + 特征高亮
```

- **上传 API 端口 8420**：业务系统对接的接口（需 API Key）。
- **查看器端口 3245**：业务系统不需要直接调用，只需要把返回的 `viewerUrl` 交给用户打开即可。

---

## 2. 基础信息

| 项 | 值 |
|---|---|
| Base URL | `http://<服务地址>:8420` |
| 协议 | HTTP（生产建议走 HTTPS/内网网关） |
| 数据格式 | `multipart/form-data`（上传）、`application/json`（响应） |
| 鉴权 | `Authorization: Bearer <API_KEY>`（或 `X-API-Key: <API_KEY>`） |
| 字符编码 | UTF-8（特征 JSON 允许带 UTF-8 BOM，服务端自动兼容） |

> `<服务地址>` 为部署环境地址（当前联调环境为 `172.16.147.195`，正式环境以实际分配为准），接口结构不变。

## 3. 鉴权

所有 `/api/v1/*` 请求必须携带 API Key，两种方式任选其一：

```
Authorization: Bearer <API_KEY>
X-API-Key: <API_KEY>
```

- 未带 / 带错 Key → **401** `{"error":"Unauthorized"}`
- `/healthz` 无需鉴权。

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| `POST` | `/api/v1/jobs` | 提交 STEP + 特征 JSON，创建任务 | 是 |
| `GET` | `/api/v1/jobs/{jobId}` | 查询任务状态与结果 | 是 |
| `GET` | `/healthz` | 健康检查（存活探测） | 否 |

## 5. 接口详情

### 5.1 提交任务 `POST /api/v1/jobs`

提交一个 STEP 文件（必填）与加工特征 JSON（可选，文本字段）。

**请求**：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `step` | file | 是 | STEP 文件，扩展名 `.step` / `.stp`（大小写均可） |
| `features` | text | 否 | 加工特征 JSON 的**字符串内容**（不是文件）；结构遵循《STEP零件加工特征JSON输出说明（报价版本）》 |

> 注意：`features` 是 **text 字段**，直接传 JSON 文本，不要用文件上传（不要带 `@`）。

**成功响应 `202 Created`**：

```json
{
  "jobId": "20260821_115310_bd87a6",
  "status": "received"
}
```

**curl 示例**：

```bash
curl -X POST http://<服务地址>:8420/api/v1/jobs \
  -H "Authorization: Bearer <API_KEY>" \
  -F "step=@D:/your/path/part.STEP" \
  -F 'features={"code":200,"partType":"rectangular_part","fixtureType":"Vise"}'
```

> PowerShell 用户注意：`-F 'features={"..."}'` 里的双引号可能被剥掉导致 400，建议改用
> `--form-string 'features={...}'` 或把 JSON 存文件后 `-F "features=$(Get-Content -Raw f.json)"`。

### 5.2 查询任务 `GET /api/v1/jobs/{jobId}`

轮询该接口获取任务状态。

**成功响应 `200 OK`**：

```json
{
  "jobId": "20260821_115310_bd87a6",
  "status": "landed",
  "createdAt": "2026-08-21T11:53:10",
  "error": null,
  "result": {
    "viewerUrl": "http://<服务地址>:3245/D:/14418/step-viewer/uploads/20260821_115310_bd87a6?file=part.STEP&features=D%3A%5C14418%5Cstep-viewer%5Cuploads%5C20260821_115310_bd87a6%5Cpart.%E7%89%B9%E5%BE%81%E8%AF%86%E5%88%AB.json",
    "taskId": "20260821_115310_bd87a6",
    "dir": "D:\\14418\\step-viewer\\uploads\\20260821_115310_bd87a6",
    "file": "part.STEP",
    "features": "part.特征识别.json"
  }
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `jobId` | string | 任务 ID（= 落盘目录名） |
| `status` | string | `received`（已接收）/ `landed`（已完成）/ `failed`（失败） |
| `createdAt` | string | 任务创建时间（本地时间，ISO 格式） |
| `error` | string\|null | 失败时的错误信息；成功为 `null` |
| `result.viewerUrl` | string | **核心交付物**：可直接打开模型的浏览器 URL |
| `result.taskId` | string | 任务目录名（= jobId） |
| `result.dir` | string | 服务端落盘绝对目录（调试用） |
| `result.file` | string | STEP 文件名 |
| `result.features` | string | 特征 JSON 落盘文件名；无特征时为 `""` |

**curl 示例**：

```bash
curl -H "Authorization: Bearer <API_KEY>" \
  http://<服务地址>:8420/api/v1/jobs/<jobId>
```

## 6. 状态机

```
接收请求 ──▶ received ──▶ landed（成功，含 result.viewerUrl）
                    └──▶ failed（失败，含 error）
```

- `received`：已接收、正在落盘（毫秒级，通常一次轮询即可看到 `landed`）。
- `landed`：文件已落盘、`viewerUrl` 可用。**此时打开 URL 即触发模型渲染；GLB 首次打开时惰性生成**，后续再开走缓存。
- `failed`：落盘失败，查看 `error`。

**建议轮询策略**：提交后间隔 200ms~500ms 查询，直到 `status` 不为 `received`，最多等待约 10 秒。

---

## 7. 状态码与错误

| HTTP 状态码 | 含义 | 典型 `error` 消息 |
|---|---|---|
| `202` | 提交成功，返回 jobId | — |
| `200` | 查询成功 | — |
| `400` | 请求参数错误 | `multipart field 'step' (a .step/.stp file) is required`<br>`Only .step/.stp files are supported`<br>`invalid features JSON: ...`<br>`expected multipart/form-data request` |
| `401` | 未鉴权 / Key 错误 | `Unauthorized` |
| `404` | 路径不存在 / jobId 不存在 | `not found` / `job not found` |
| `413` | 请求体超限（默认 100 MiB） | `request body exceeds ... bytes` |
| `500` | 服务端异常 | 具体错误信息 |

统一错误响应格式：`{"error": "<原因>"}`。

---

## 8. 对接流程（推荐实现）

```text
1) POST /api/v1/jobs
      -F step=<文件> -F features=<JSON文本>
      → 202 {jobId}
2) 循环 GET /api/v1/jobs/{jobId}，直至 status ∈ {landed, failed}
3) landed → 取 result.viewerUrl
      → 下发给用户（浏览器打开 / iframe 嵌入 / 前端跳转）
   failed → 读取 error，向业务侧提示失败
```

**关键约定**：

- `viewerUrl` 中的路径（`/D:/.../uploads/<jobId>`）是**服务端本地路径**，业务系统无需理解，原样交付即可；用户浏览器打开时由服务端自行解释。
- `viewerUrl` 可在多台机器打开（只要它们能访问 `<服务地址>:3245`）。
- 特征高亮依赖 URL 中的 `features=` 参数；未传特征 JSON 时无高亮但模型正常展示。

---

## 9. 示例（完整联调）

```bash
# ① 提交
JOB=$(curl -s -X POST http://<服务地址>:8420/api/v1/jobs \
  -H "Authorization: Bearer <API_KEY>" \
  -F "step=@part.STEP" \
  -F 'features={"code":200,"partType":"rectangular_part"}')
echo "$JOB"
# {"jobId":"20260821_...","status":"received"}

JOB_ID=$(echo "$JOB" | python -c "import sys,json;print(json.load(sys.stdin)['jobId'])")

# ② 轮询
curl -H "Authorization: Bearer <API_KEY>" \
  http://<服务地址>:8420/api/v1/jobs/$JOB_ID
# → status=landed 后取 result.viewerUrl

# ③ 把 viewerUrl 交给用户浏览器打开
```

## 11. 安全部署（生产环境必读）

> 本服务的两个端口性质不同，安全要求也不同。

### 11.1 端口性质

| 端口 | 鉴权 | 面向对象 | 安全等级 |
|---|---|---|---|
| `8420` 上传 API | 有（Bearer API Key） | 业务系统（程序） | 可对外，但建议 HTTPS |
| `3245` 查看器 | **无** | 最终用户（浏览器） | **仅限可信内网** |

### 11.2 必做项

1. **查看器 `3245` 绝不直接暴露公网**。`server_py.server` 是**无认证**服务、按 URL 路径读取本地 CAD 文件（`/__cad/asset?file=...`）。启动时若绑定非回环地址会打印警告。
   - 仅限可信内网访问；对公网/跨信任域使用时，**必须**置于带鉴权的反向代理之后。
2. **统一走反向代理**（Nginx/Caddy）：
   - TLS 终止（`https://<域名>:443`）；
   - `8420` 与 `3245` 都只通过代理暴露，不直接暴露裸端口；
   - 在代理层加访问控制（IP 白名单 / basic-auth / OAuth2）。
3. **API Key 管理**：不要硬编码/写进命令行（`ps` 可见）。用 `--api-key-file` 或 `$VIEWER_API_KEY_FILE` 从受限文件/密钥管理器读取；定期轮换。
4. **`viewerUrl` 含服务端本地绝对路径**（如 `.../D:/.../uploads/<jobId>?file=...`）——这是信息泄露面，仅限在可信范围内分发；业务系统不应把该 URL 长期存档或转发到不可信方。
5. **文件访问范围**：查看器只服务 `uploads/` 等受控目录内、且为 CAD 白名单扩展名的文件（`asset_path_for_file_ref` 有根目录 + 扩展名 + 隐藏目录三重守卫），但前提是**绑定/代理边界正确**。
6. **限流**：在反向代理层对 `8420` 做请求速率限制（如 Nginx `limit_req`），防止任务提交滥用。
7. **日志与审计**：生产开启访问日志（记录时间/方法/路径/状态码/耗时），保留一定周期；`--debug` 仅开发/联调环境开启。

### 11.3 典型生产拓扑

```
公网/业务系统 ──HTTPS──▶ 反向代理(Nginx，TLS+限流+鉴权)
                            ├──▶ :8420 上传 API（内网，API Key）
                            └──▶ :3245 查看器（内网，无认证，仅可信网络可达）
```
